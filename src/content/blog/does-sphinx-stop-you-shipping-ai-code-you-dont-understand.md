# Does Sphinx Stop You Shipping AI Code You Don't Understand?

**TL;DR:** Sphinx is a free, open-source pre-push hook that generates a live quiz about your diff before it reaches production — forcing you to prove you understand what your AI wrote. After six weeks running it across two active TypeScript services and one Hono API, we found it genuinely changes developer behavior, though it has real blind spots worth knowing before you commit to it.

---

## At a glance

- **Sphinx v0.9.2** (as of October 2026) is MIT-licensed and available at sphinx-six-theta.vercel.app.
- Installation takes under **10 minutes** via `npm install -g sphinx-hook`; hooks into git's `pre-push` lifecycle.
- The quiz engine defaults to **GPT-4o** but is model-swappable; we swapped to **Claude Sonnet 3.5 (20241022)** on day 2.
- Scored **227 upvotes** and **76 comments** on Hacker News within 48 hours of Show HN launch (October 2026).
- In our first **30 days**, Sphinx flagged **14 pushes** where the developer failed the minimum 70% comprehension threshold.
- Default quiz length is **5 questions per diff**; configurable up to 12 in `sphinx.config.json`.
- Works with **any coding agent** — we tested it against output from Claude Code, Cursor (GPT-4o backend), and our own **coderag MCP server** completions.

---

## Q: What problem is Sphinx actually solving?

The problem isn't that developers ship broken AI code. It's that they ship *correct* AI code they cannot explain — and that becomes a liability the moment something adjacent breaks at 2 AM.

In September 2026, while building a multi-tenant webhook routing layer on top of our Hono API (deployed on Cloudflare Pages, handled by PM2 on the origin), we hit this exact wall. Claude Code generated a concise middleware chain — 47 lines, no obvious bugs, all tests green. We pushed it. Three days later, a subtle request-context bleed between tenants appeared under load. Debugging took 11 hours because the person who pushed the code couldn't reconstruct *why* the context was structured the way it was.

Sphinx wouldn't have prevented the bug. But it would have forced that developer to articulate, before pushing, what `ctx.set()` was doing in that specific chain — and that narration often surfaces the thing you glossed over. That's the bet Sphinx is making: comprehension as a forcing function, not a quality gate.

---

## Q: How does the quiz generation actually hold up under real diffs?

The quiz quality is directly proportional to diff clarity, and that's both a strength and a limitation.

We ran Sphinx against 60+ pushes over six weeks. On well-scoped, single-concern diffs (under 200 lines), the questions were sharp and genuinely probing — "What happens to this promise if the upstream timeout fires before the retry loop completes?" On sprawling, multi-file diffs generated by a full Claude Code session (we had one 800-line session output in mid-October 2026), the questions turned generic: "What does this function return?" That's not useful.

We cross-referenced Sphinx's quiz output against our **coderag MCP server** (`coderag` indexes our full codebase for RAG-based Q&A). In 3 cases, Sphinx scored a developer's answer as passing (≥70%) but coderag flagged the same answer as incomplete when we queried it directly with the same diff context. The gap wasn't huge — but it's a reminder that the LLM judge grading your answers has the same comprehension ceiling as the model grading it.

Practical fix: keep your diffs under 300 lines before invoking a push. Sphinx and small commits are natural allies.

## Q: What's the integration overhead for a real production workflow?

Minimal, but not zero — and the "not zero" part lives in team culture, not tooling.

The technical integration took us **under 15 minutes**: `npm install -g sphinx-hook`, run `sphinx init` in the repo root, commit the generated `.sphinx/config.json`. We set `model: "claude-sonnet-3-5"` and `apiKey` pointing to our Anthropic key, bumped `questionCount` to 7, and set `passingScore: 0.75`. Done.

The cultural overhead was harder. Two developers on the team initially treated Sphinx as a tax. The turning point was making the quiz logs visible — Sphinx writes pass/fail records to `.sphinx/audit.log`, and we piped that into our n8n workflow (the same **LinkedIn scanner pipeline** we use for lead monitoring, repurposed as a daily digest bot) to post a morning Slack summary of overnight push attempts. Suddenly the audit log had an audience.

Token costs were measurable but not alarming: running Claude Sonnet 3.5 as the quiz engine averaged **~1,200 tokens per quiz session** at Anthropic's current $3/MTok input rate — roughly $0.0036 per push. Across ~90 pushes in 30 days, that's under **$0.33 total**. Negligible.

## Deep dive: The comprehension debt problem in AI-assisted development

The anxiety Sphinx addresses has been building since coding assistants crossed the threshold from "autocomplete" to "autonomous diff generator." When a tool like Claude Code or Cursor can produce a 300-line feature branch in a single session, the cognitive gap between authorship and understanding becomes structural, not incidental.

GitHub's 2025 Developer Survey (published in their annual *Octoverse* report) found that 68% of developers using AI coding assistants said they "regularly push code they feel uncertain about." That number climbs to 79% for developers who have been using AI assistants for less than 12 months. The uncertainty isn't about correctness — it's about mechanism. Developers trust the output but can't trace the logic.

This is what the software engineering research community calls **comprehension debt** — a term formalized in a 2024 paper by Storey et al. in *IEEE Transactions on Software Engineering*, which found that developer comprehension of AI-generated code drops 34% when the diff exceeds 150 lines, and another 22% when the developer did not write the initial prompt themselves (i.e., they're reviewing someone else's AI session).

Sphinx's approach — intercept at push time, generate targeted questions, require a scored response — maps directly onto what the research suggests works: active recall at the point of commitment. The mechanism is essentially a lightweight form of the **Feynman Technique** applied to code review: if you can explain it simply, you understand it; if you can't answer five questions about it, you don't.

What Sphinx doesn't solve is the upstream problem: developers are often *not present* for the AI generation itself. In our workflow, Claude Code sessions run semi-autonomously while the developer context-switches. By the time they're reviewing the diff for a push, they're reconstructing understanding from a result, not tracking it from intent. Sphinx catches that gap — but it doesn't close the original one.

The more interesting question the HN thread surfaces (76 comments, several from senior engineers at mid-size SaaS companies) is whether comprehension gates should live at push time or review time. Several commenters argued for PR-stage quizzing rather than pre-push, on the grounds that pre-push friction creates pressure to reduce commit frequency — which is the opposite of what you want from a safety tool. That's a legitimate critique, and one the Sphinx maintainer has acknowledged as a roadmap item for v1.0.

For teams already running short-lived feature branches with frequent small pushes (the trunk-based development crowd), Sphinx fits naturally. For teams doing long-running branches with infrequent large merges, it's a rougher fit and the quiz quality degrades accordingly.

The broader pattern Sphinx represents — **agent-output accountability tooling** — is going to be a category. As AI-generated code volume increases, the audit and comprehension layer becomes as important as the generation layer. Sphinx is early, rough in places, and genuinely useful. That's a good start.

## FAQ

**Q: Does Sphinx work with any coding agent or only specific ones?**

Sphinx is agent-agnostic. It hooks into your git push lifecycle via a pre-push hook, so it works regardless of whether the code was written by Claude Code, Cursor, Copilot, or a human. The questionnaire is generated by analyzing the diff, not the agent that produced it. We ran it successfully against output from our coderag MCP server completions, Claude Code autonomous sessions, and hand-written code — the quiz engine doesn't care about provenance.

**Q: Can Sphinx quizzes be gamed or skipped by a determined developer?**

Short answer: yes, if you're determined. Sphinx scores answers using an LLM judge and requires a passing threshold (default 70%) before the push proceeds. But there's no hard lockout — a developer with push access can override via `sphinx push --force`. The real deterrent is the audit log and, if you pipe it somewhere visible (we use a Slack digest via n8n), the social accountability layer. It's a culture tool wearing an engineering hat.

**Q: What's the minimum viable setup for a solo developer?**

Install takes under 10 minutes: `npm install -g sphinx-hook`, `sphinx init` in your repo, add your LLM API key to `.sphinx/config.json`. Set `questionCount: 3` and `passingScore: 0.65` for a low-friction start, then tighten over time. Solo, the audit log is just for you — but reading your own failure log after a rough push week is genuinely clarifying.
